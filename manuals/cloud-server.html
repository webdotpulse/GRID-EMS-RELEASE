GRID-EMS-SERVER Connection Guide

Learn how to securely link your local GEMS Raspberry Pi edge node to GRID-EMS-SERVER (https://ems.newenergygrid.com) for multi-site fleet monitoring, continuous high-frequency telemetry ingestion, and bidirectional remote control with zero inbound port forwarding.

Download Printable PDF Manual

1. Overview & Communication Architecture

GEMS operates under a decentralized, local-first architecture. When connected to GRID-EMS-SERVER, the edge controller mirrors its real-time telemetry into the cloud and accepts dispatched fleet commands without ever requiring inbound public firewall ports.

Settings → Central Cloud Server: Showing live pairing status, round-trip sync latency, and dispatched cloud command audit trail.
Decentralized Resilience

The edge system never relies on cloud availability for real-time electrical safety or optimization. If internet access is interrupted, Flanders capacity peak shaving, Modbus EV throttling, solar self-consumption, and battery schedules continue unaffected.

2. Network & Outbound Firewall Rules

All network communication initiated by GEMS is strictly outbound over standard HTTPS (Port 443).

Destination Protocol Port Direction Function
ems.newenergygrid.com HTTPS (TLS 1.3) 443 Outbound Pairing (/register), Telemetry (/telemetry), Ack (/commands/.../ack)
Local Gateway / DNS DNS 53 Outbound Resolving hostname to cloud IP
pool.ntp.org NTP 123 Outbound Time synchronization for valid TLS verification

3. Pairing & Authentication Handshake

Pairing binds the physical Raspberry Pi edge controller to your customer account in the central portal using a one-time token.

  1. Log in to https://ems.newenergygrid.com and navigate to Fleet → Add Node to generate an edge pairing token (e.g., PAIR-8821-X9K2).
  2. In the GEMS Web UI, navigate to Settings → Cloud Server.
  3. Paste your pairing token and click Pair & Connect Now.
  4. GEMS transmits the token along with the hardware serial number to /api/v1/device/register. The server replies with a unique device_id and high-entropy device_secret.
  5. GEMS stores these credentials locally in the SQLite database and retires the pairing token.

5. Dispatched Remote Commands Catalog

When telemetry is ingested, the cloud server piggybacks any pending remote actions in the HTTP response:

Command Payload Keys Description
set_strategy_mode mode, peak_limit_kw Switches between Flanders, Eco, Dynamic Arbitrage, or Zero-Export strategies.
set_battery_mode device_id, mode Forces inverter battery charging or grid arbitrage discharge.
throttle_ev_charger device_id, max_current_a Adjusts charging current setpoint (6A–32A) for peak shaving or solar matching.
set_relay relay_id, state Toggles physical contactor or smart relay for heat pump boost or domestic hot water.
reboot delay_sec Gracefully reboots the edge Raspberry Pi system.

6. Step-by-Step UI Commissioning

1

Open Settings → Cloud Server

Navigate to Settings in the sidebar and click the Cloud Server tab.

2

Configure Endpoint & Credentials

Confirm the server URL (https://ems.newenergygrid.com) and enter your pairing token.

3

Pair & Verify Telemetry Stream

Click Pair & Connect Now. Verify that the indicator turns green (● ONLINE & SYNCED) and latency displays around 15–30 ms.

7. Field Troubleshooting & Diagnostic Commands

Bash (Cockpit Port 9090 or SSH) 
# Monitor live edge cloud synchronization daemon
sudo journalctl -u gems -f | grep CloudManager

# Test DNS and outbound HTTPS connectivity
curl -Iv https://ems.newenergygrid.com/api/status

# Check stored credentials in edge database
sqlite3 /var/lib/gems/gems.db "SELECT id, cloud_enabled, cloud_server_url, cloud_device_id FROM site_settings;"
