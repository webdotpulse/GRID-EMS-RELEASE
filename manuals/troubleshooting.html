Troubleshooting, Diagnostics & FAQ Manual

Step-by-step diagnostic workflows, common error codes, hardware bus inspection commands, and answers to frequently asked questions.

1. Modbus TCP & RTU Troubleshooting

When a device fails to communicate, the real-time Logger will output descriptive error messages. Review the matrix below to resolve the root cause:

Live Diagnostics Logger: Live streaming Modbus poll attempts, CRC check warnings, and instant log export.
Error Message Underlying Cause Resolution Step
connection refused (ECONNREFUSED) Target IP is reachable, but Modbus TCP service is disabled or listening on a different port. Enable Modbus TCP in inverter settings (e.g. Huawei FusionSolar → Dongle Settings → Modbus TCP: Unrestricted). Check port (typically 502 or 1502).
i/o timeout Target IP is offline, blocked by firewall, or device is in deep sleep. Verify IP with ping <ip>. Inverters shut down communication during nighttime if AC grid power is disconnected or solar panels produce 0W.
modbus: response slave id mismatch The inverter is configured with a different Modbus Slave Unit ID. Huawei default is 1 or 2; SMA is 126 or 3; SolarEdge is 1; GoodWe is 247. Check device manual.
modbus: exception 'Illegal Data Address' The template requested a holding/input register not supported by your inverter firmware. Upgrade inverter firmware via manufacturer installer app or verify standard SunSpec 16-bit register offset.
CRC check failed / framing error RS485 electrical noise, incorrect baud rate, or missing termination. Check RS485 baud rate (9600 vs 19200 vs 115200), install 120Ω termination resistors at both bus ends, and verify shielded twisted pair wiring.

2. P1 DSMR Smart Meter Diagnostics

Baud Rate & Inversion Discrepancy

Standard DSMR 5.0 meters (Fluvius Belgium, Dutch Smart Meters) operate at 115200 baud, 8 data bits, no parity, 1 stop bit (8N1) and output inverted serial data. Older DSMR 2.2 / 3.0 meters operate at 9600 baud, 7 data bits, even parity, 1 stop bit (7E1). Ensure your USB optical probe features active signal inversion circuitry.

Testing P1 Data Stream in Terminal

Access Cockpit Terminal on port 9090 and execute the following commands:

Bash / Terminal 
# 1. Verify USB serial device is detected
ls -l /dev/ttyUSB*

# 2. Configure serial port speed (DSMR 5.0)
stty -F /dev/ttyUSB0 115200 cs8 -cstopb -parenb

# 3. Read raw telegram output (should stream valid text starting with '/')
cat /dev/ttyUSB0

# Example expected output:
# /FLU5\253769484_A
# 1-0:1.8.1(001234.567*kWh)
# 1-0:1.7.0(01.250*kW)
# 1-0:31.7.0(005*A)
# !52C1

3. OCPP EV Charger Connection Diagnostics

Symptom Root Cause Diagnostic Action
Charger status stays "Offline" EV Charger cannot reach WebSocket URL or DNS lookup failed. Ensure the charger configuration uses the raw IP: ws://192.168.1.50:8080/api/ocpp/<ChargerID> instead of ems.local if the charger does not support mDNS resolution.
WebSocket 404 / 400 Bad Request ChargePoint ID in URL does not match the configured Host field in GEMS. Verify that the ID appended to /api/ocpp/<ID> exactly matches the Host value entered in the GEMS Add Device dialog.
Charging current not changing Charger ignores SetChargingProfile commands. Ensure the charger is in "Auto" or "External CSMS" mode in the manufacturer app. If set to manual override, external control profiles are rejected.
Network Scanner Diagnostic: Validating local IP addresses, hostname bindings, and open ports (502 Modbus, 80/443 HTTP, 8080 OCPP).

4. NVMe SSD & Bootloader Diagnostics (Patriot P300 & Pi 5)

If your Raspberry Pi 5 does not detect the Patriot P300 128GB M.2 SSD or fails to boot from the NVMe HAT, work through the diagnostic matrix below:

Symptom Root Cause Diagnostic & Resolution Command
Pi boots to blank screen / ACT LED doesn't flash EEPROM is set to factory BOOT_ORDER=0xf41 and not configured for PCIe probe. Flash the official Bootloader → NVMe/PCIe Boot image to a MicroSD card using Raspberry Pi Imager, boot for 5s until HDMI screen turns solid green.
lspci shows no NVMe device FPC ribbon cable is inverted, loose, or dtparam=pciex1 is missing. Ensure gold pins face inward toward USB/Ethernet ports on Pi 5. Verify /boot/firmware/config.txt contains dtparam=pciex1 and dtparam=pciex1_gen=2.
Kernel dmesg: pcieport link down Signal integrity failure or power supply sag. Ensure you are using the official 27W USB-C PD power supply (included in db-tronic kit). 15W phone chargers will brownout during PCIe link training.
lsblk shows no /dev/nvme0n1 SSD not seated in M.2 key or missing kernel driver module. Re-seat the Patriot P300 SSD at a 30° angle, tighten M2 screw. Run sudo modprobe nvme and sudo dmesg | grep -i nvme in Cockpit terminal.
NVMe Inspection Commands (Cockpit Terminal) 
# 1. Check if PCIe Controller detects Silicon Motion / Patriot NVMe:
lspci -v

# 2. Check if NVMe block device is registered:
lsblk -f

# 3. Check EEPROM boot order and PCIe probe status:
sudo rpi-eeprom-config

# 4. View real-time PCIe kernel link state:
sudo dmesg | grep -i -E "pci|nvme"

5. SQLite & Storage Health Diagnostics

GEMS employs SQLite Write-Ahead Logging (WAL) and memory caching to prevent SD card corruption. You can inspect database health directly via terminal:

SQLite Diagnostic Commands 
# Open SQLite database
sqlite3 /opt/gems/gems.db

-- 1. Check WAL mode status (should return 'wal')
PRAGMA journal_mode;

-- 2. Verify database integrity (should return 'ok')
PRAGMA integrity_check;

-- 3. Check WAL checkpoint status
PRAGMA wal_checkpoint(PASSIVE);

-- 4. Check total recorded measurement count
SELECT COUNT(*) FROM measurements;

.exit

7. GRID-EMS-SERVER & Central Cloud Diagnostics

For complete packet specifications, pairing procedures, and architecture details, refer to the dedicated GRID-EMS-SERVER Connection Guide or download the Printable Server Manual (PDF).

Symptom / Error Message Underlying Cause Diagnostic & Resolution Procedure
Handshake failed: dial tcp lookup... DNS resolution failure on Raspberry Pi adapter. Verify local gateway DNS in Cockpit terminal: curl -Iv https://ems.newenergygrid.com/api/status.
HTTP 401 Unauthorized Device secret invalidated or de-registered in portal. GEMS automatically attempts re-registration. If token expired, generate a new pairing token in portal and re-pair.
Telemetry push network error: timeout Outbound port 443 blocked or high packet loss. Ensure firewall allows outbound TCP 443. Check Ethernet cable connection.
Missing remote commands Commands not yet published to cloud queue. Check Dispatched Cloud Commands audit table in Settings → Cloud Server. Commands execute on next 2s-5s telemetry poll.
Cloud Service Journalctl 
# Monitor live cloud synchronization daemon
sudo journalctl -u gems -f | grep CloudManager

8. Frequently Asked Questions (FAQ)

Why is there no vehicle API or car SOC tracking?

By design philosophy, GEMS operates exclusively on real-time local hardware measurements. Proprietary car cloud APIs are notoriously brittle, subject to frequent breaking changes, battery drain, and rate limits. The EMS controls EV charging reliably via native EV charger hardware setpoints.

Why is CPU usage not displayed in System Info?

GEMS is strictly optimized for minimal memory and CPU overhead on Raspberry Pi boards. CPU telemetry polling is intentionally excluded from the frontend to preserve system lightness. Full hardware diagnostics remain accessible via Cockpit on port 9090.

How fast does zero-export response happen?

Smart meters are queried on a fast 1-second ticker. When grid export is detected, active inverter curtailment setpoints and EV charging commands are dispatched immediately to keep export as close to 0 W as physically possible.

How do I reset the Cockpit admin password?

Access the terminal via SSH or an attached keyboard and run sudo passwd admin. Enter your new password twice.

How to recover from an interrupted system update?

If an over-the-air update was interrupted by a power failure, run sudo dpkg --configure -a followed by sudo apt-get install -f in Cockpit Terminal.

Does the system work without internet access?

Yes! All local control loops (Eco mode, Flanders peak shaving, Zero-export, Modbus polling, and Native OCPP) execute 100% locally on the Raspberry Pi without any cloud dependency. Day-Ahead EPEX spot prices simply retain the last fetched 24-hour table if internet is disconnected.
