⚡ Montage du SSD M.2 NVMe & Configuration EEPROM

Lors de l'assemblage d'un Raspberry Pi 5 neuf avec une base M.2 NVMe PCIe et un SSD NVMe, le Pi 5 ne démarre pas immédiatement sur le SSD : l'EEPROM d'usine est programmée pour démarrer uniquement sur MicroSD (BOOT_ORDER=0xf41) sans sonder le bus PCIe au démarrage.

Pourquoi le Pi 5 ne détecte pas le SSD M.2 NVMe par défaut

1. Ordre d'amorçage EEPROM : Le chargeur d'amorçage d'usine ignore le stockage NVMe tant que le mode NVMe (0x6) et PCIE_PROBE=1 ne sont pas activés dans l'EEPROM.
2. Overlay PCIe du noyau : Le noyau Linux requiert dtparam=pciex1 dans /boot/firmware/config.txt.
3. Sens de la nappe FPC : Les pistes dorées de la nappe 16 broches doivent être orientées vers l'intérieur, côté ports Ethernet/USB sur le Raspberry Pi 5.

Méthode 1 : Mise à jour rapide en 3 minutes (via Raspberry Pi Imager)

  1. Insérez une carte MicroSD dans votre PC ou Mac.
  2. Ouvrez Raspberry Pi Imager → Choisir le modèle : Raspberry Pi 5.
  3. Cliquez sur Choisir le système (Choose OS) → Misc utility images → Bootloader → NVMe/PCIe Boot.
  4. Sélectionnez votre carte MicroSD puis cliquez sur Écrire (Write).
  5. Insérez la carte dans le Raspberry Pi 5 (avec le SSD M.2 NVMe monté sur la carte d'extension) et branchez l'alimentation officielle 27W.
  6. Après 5 à 10 secondes, la LED verte ACT clignote rapidement et l'écran HDMI devient vert fixe, confirmant la mise à jour permanente de l'EEPROM (BOOT_ORDER=0xf461, PCIE_PROBE=1).
  7. Débranchez l'alimentation, retirez la carte MicroSD, flashez gems-os-image.img.xz directement sur le SSD NVMe et remettez sous tension. Le système démarre sur NVMe en moins de 8 secondes !

Méthode 2 : Flasher le SSD NVMe directement via le Terminal Web Cockpit

Si vous ne disposez pas d'un boîtier USB-vers-NVMe externe sur votre ordinateur, vous pouvez configurer l'EEPROM et écrire l'image sur le SSD NVMe directement depuis le terminal Cockpit (http://ems.local:9090) après avoir démarré sur carte MicroSD :

Terminal Cockpit (Port 9090) 
# 1. Mettre à jour l'EEPROM pour activer le bus PCIe et l'amorçage NVMe
sudo rpi-eeprom-config --edit
# Vérifiez que BOOT_ORDER=0xf461 et PCIE_PROBE=1 sont définis, puis enregistrez (Ctrl+O, Ctrl+X)

# 2. Télécharger et écrire GEMS directement sur le SSD NVMe (/dev/nvme0n1)
curl -LO https://github.com/webdotpulse/GRID-EMS-RELEASE/releases/latest/download/gems-os-image.img.xz
xzcat gems-os-image.img.xz | sudo dd of=/dev/nvme0n1 bs=4M status=progress conv=fsync

# 3. Éteindre, retirer la carte MicroSD et redémarrer !
sudo poweroff

Option A : Image Raspberry Pi OS Préconfigurée (Recommandé)

La méthode la plus rapide et la plus fiable pour déployer GEMS consiste à utiliser l'image officielle préconfigurée basée sur Raspberry Pi OS Lite (Bookworm ARM64).

Contenu inclus dans l'image système
  • Noyau & Système de fichiers optimisés : Réglages SQLite WAL, partitions temporaires en mémoire vive et usure minimale du support de stockage.
  • Proxy inverse Nginx : Écoute automatiquement sur le port 80 et redirige proprement les flux WebSocket et SSE vers GEMS sur le port 8080.
  • Environnement Kiosque Wayfire : Compositeur Wayland ultra-léger démarrant Chromium en plein écran sur http://ems.local.
  • Console Web Cockpit : Terminal root complet et supervision matérielle préinstallés sur le port 9090 (connexion avec votre compte administrateur Linux).
  • Raspberry Pi Connect : Préparé pour l'assistance et l'accès distant sécurisés sans redirection de port.

Instructions d'écriture de l'image

  1. Téléchargez la dernière archive gems-os-image.img.xz depuis la page GitHub Releases.
  2. Insérez une carte MicroSD rapide (Classe 10 / U3, 8 Go minimum) ou un adaptateur NVMe dans votre ordinateur.
  3. Ouvrez BalenaEtcher ou Raspberry Pi Imager.
  4. Sélectionnez directement le fichier .img.xz téléchargé (aucune décompression préalable nécessaire), choisissez le lecteur cible et cliquez sur Flash!.
  5. Une fois l'écriture et la vérification terminées, insérez le support dans votre Raspberry Pi et branchez l'alimentation.
Premier accès 
# Accès via mDNS dans votre navigateur local :
http://ems.local
# Ou directement par nom d'hôte :
http://ems

# Terminal Web Cockpit intégré :
https://ems.local:9090
# Connectez-vous avec les identifiants administrateur Linux provisionnés (ou définis dans Raspberry Pi Imager)

Option B : Installation par Paquet Debian (.deb)

Si vous disposez déjà d'une distribution Raspberry Pi OS ou Debian/Ubuntu ARM64 opérationnelle, vous pouvez installer directement le paquet autonome.

1. Télécharger et installer le paquet

Bash / Terminal 
# Télécharger le dernier paquet Debian ARM64
TAG=$(curl -fsSL https://api.github.com/repos/webdotpulse/GRID-EMS-RELEASE/releases/latest | grep -o '"tag_name": *"[^"]*"' | cut -d'"' -f4)
curl -fLO "https://github.com/webdotpulse/GRID-EMS-RELEASE/releases/download/${TAG}/gems_${TAG#v}_arm64.deb"

# Installer le paquet
sudo dpkg -i "gems_${TAG#v}_arm64.deb"

# Résoudre automatiquement les éventuelles dépendances manquantes
sudo apt-get install -f -y

2. Gestion du service Systemd

Le paquet Debian crée un utilisateur système dédié gems, installe les binaires et ressources dans /opt/gems et enregistre le démon gems.service ainsi que le service de mise à jour gems-updater.path :

Opération Commande terminal Description
Vérifier l'état sudo systemctl status gems.service Vérifie l'état d'exécution actif et l'empreinte mémoire.
Redémarrer le service sudo systemctl restart gems.service Redémarre proprement le moteur backend et recharge le cache SQLite.
Arrêter le service sudo systemctl stop gems.service Écrit tous les tampons de mesures en mémoire vers SQLite avant l'arrêt complet.
Suivre les journaux sudo journalctl -u gems.service -f -n 100 Affiche en direct les journaux du démon depuis le journal systemd.

Terminal Web Cockpit & Administration Système

Cockpit offre une interface web d'administration Linux claire et complète accessible sur le port 9090.

Sécurité des identifiants d'administration

Connectez-vous à Cockpit à l'aide de votre compte administrateur système Linux. Nous recommandons vivement de renouveler le mot de passe administrateur lors de la mise en service initiale via Cockpit → Comptes ou via la commande sudo passwd.

Grâce à Cockpit, vous pouvez :

  • Ouvrir un terminal bash complet avec privilèges root directement dans votre navigateur sans client SSH tiers.
  • Visualiser en temps réel la charge processeur, la mémoire vive et le débit réseau.
  • Inspecter et redémarrer les unités systemd (gems.service, nginx.service, wayfire.service).
  • Consulter les journaux du noyau (dmesg) et du système.

Raspberry Pi Connect (Accès distant sécurisé)

Raspberry Pi Connect permet un accès distant chiffré à votre contrôleur GEMS depuis n'importe quel navigateur externe, sans redirection de port ni VPN.

  1. Ouvrez le terminal web Cockpit sur http://ems.local:9090.
  2. Exécutez la commande suivante avec l'utilisateur de session kiosque pour activer le service et lancer l'association :
    Terminal 
    sudo loginctl enable-linger gems-kiosk
rpi-connect signin
  3. Cliquez ou copiez l'URL d'authentification affichée dans le terminal afin de lier l'unité à votre identifiant Raspberry Pi ID.
  4. Rendez-vous sur connect.raspberrypi.com depuis votre navigateur et sélectionnez ems pour un accès shell distant chiffré. Pour des raisons de confidentialité et de sécurité, le partage d'écran sans surveillance est désactivé par défaut avec notifications de connexion activées.

Vérification de l'installation & État du système

Une fois démarré, ouvrez l'interface web sur http://ems.local (ou via l'adresse IP du Raspberry Pi) et rendez-vous dans Paramètres → Infos système pour vérifier la configuration réseau et le numéro de version logicielle :

Onglet Infos système : Identité de l'unité, interfaces réseau et version logicielle OTA.

Câblage matériel : Bus RS485 & Liaison Modbus RTU

Lors du raccordement d'onduleurs solaires, de compteurs d'énergie ou de bornes de recharge en Modbus RTU (série), un câblage RS485 rigoureux est indispensable à la fiabilité des échanges.

Signal Couleur de fil habituelle Description & Polarité
A (D+ / TxD+ / RxD+) Blanc / Liseré bleu Ligne de données différentielle non inverseuse (+).
B (D- / TxD- / RxD-) Bleu uni Ligne de données différentielle inverseuse (-).
GND (COM) Marron / Fil de référence Masse de référence commune du signal. Évite les dérives de potentiel en mode commun.
Blindage (Shield) Tresse métallique nue Relier à la terre en UN SEUL point uniquement (côté adaptateur USB du Raspberry Pi).
Résistances de terminaison (120Ω)

Pour toute longueur de bus RS485 supérieure à 10 mètres, installez une résistance de 120Ω (0,25W) entre les bornes A et B aux deux extrémités physiques de la chaîne (sur l'adaptateur USB et sur le dernier esclave). Proscrivez les câblages en étoile ou en dérivation.

Brochage RJ12 du Port P1 Compteur Intelligent DSMR

Les compteurs numériques communicants en Belgique (Fluvius, ORES, RESA, Sibelga) et aux Pays-Bas utilisent un connecteur RJ12 (6P6C) sur le port P1 pour transmettre les télégrammes série DSMR :

Broche RJ12 Nom du signal Sens Fonction
Broche 1 Alimentation +5V Sortie compteur Alimente la sonde optique isolée ou le convertisseur USB (DSMR 5.0+ fournit jusqu'à 250 mA).
Broche 2 Demande de données (RTS) Entrée compteur Maintenir à l'état HAUT (+5V) pour activer l'émission des télégrammes par le compteur.
Broche 3 Masse données (Data GND) - Masse de référence pour les signaux logiques.
Broche 4 NC - Non connectée.
Broche 5 Sortie données (RxD) Sortie compteur Flux série ASCII inversé (115200 bauds, 8N1 en DSMR 5.0 ; 9600 bauds, 7E1 en DSMR 2/3).
Broche 6 Masse alimentation (Power GND) - Masse de retour de l'alimentation +5V.
Activation du port client P1 auprès du gestionnaire de réseau

En Belgique (Fluvius, ORES, RESA, Sibelga), le port client P1 est désactivé par défaut pour des raisons de confidentialité. Vous devez activer l'ouverture du port P1 sur le portail en ligne de votre gestionnaire de réseau (par ex. sur Mijn Fluvius ou via le portail ORES/RESA) avant que le compteur ne transmette ses télégrammes.
