💡 Autonomie Edge & Connectivité Cloud 100 % Optionnelle
Garantie Local-First & Intégration Optionnelle : GEMS est conçu dès l'origine comme un nœud edge décentralisé. La connexion à GRID-EMS-SERVER est possible et 100 % optionnelle. Toutes les boucles de régulation locales — y compris le délestage VE Modbus à la sous-seconde, le routage du surplus solaire, l'écrêtage capacitaire en Flandre, la compensation intelligente aux Pays-Bas, l'arbitrage batterie et l'automatisation des relais — s'exécutent en totale autonomie sans aucune dépendance au cloud ni à Internet. Lorsqu'elle est activée, l'intégration cloud ajoute l'accès distant chiffré, la supervision multi-sites et le suivi automatisé.

1. Architecture & Topologie des Communications

GEMS communique avec GRID-EMS-SERVER via un pipeline de poussée télémétrique et d'interrogation exclusivement sortant. Dans cette architecture, le contrôleur edge initie toutes les connexions via HTTPS, éliminant totalement le besoin d'ouvrir des ports entrants sur le routeur, de configurer un DNS dynamique ou de disposer d'une adresse IP publique fixe chez le client.

1.1 Principes Architecturaux Fondamentaux

  • Aucune Exposition Entrante du Pare-feu : Les routeurs résidentiels et tertiaires ne nécessitent aucune redirection de port (port forwarding), zone DMZ ou UPnP. Toutes les communications s'effectuent en HTTPS sortant vers le port 443.
  • Agrégation Télémétrique : À chaque intervalle de synchronisation (configurable entre 2 s et 60 s, par défaut 5 s), le moteur edge regroupe les mesures temps réel des onduleurs, batteries, compteurs, bornes VE, pompes à chaleur et tarifs au sein d'une charge utile JSON unique.
  • Commandes Distantes Embarquées (Piggybacking) : Plutôt que d'ouvrir des canaux entrants persistants ou d'exiger des VPN complexes, le serveur cloud joint les commandes en attente à la réponse HTTP 200 de l'envoi télémétrique. Le contrôleur edge exécute l'ordre puis acquitte son statut lors de la requête suivante.
  • Isolation Matérielle à la Sous-Milliseconde : La goroutine CloudManager s'exécute de manière totalement découplée des workers d'acquisition matérielle locale. Une liaison WAN lente ou une indisponibilité cloud ne provoque jamais de gigue Modbus ni de retard sur l'écrêtage de pointe.

2. Prérequis Réseau & Pare-feu

Avant de mettre en service la connexion cloud sur site, vérifiez que le réseau local respecte les critères de routage sortant suivants :

Hôte de Destination Protocole Port Direction Fonction
ems.newenergygrid.com (ou hôte personnalisé) HTTPS (TLS 1.2/1.3) TCP 443 Sortant Enregistrement de l'unité, ingestion de télémétrie, acquittement des commandes distantes
DNS Local (ex. 1.1.1.1, 8.8.8.8, Passerelle) DNS UDP/TCP 53 Sortant Résolution du nom de domaine du serveur cloud
Serveur de Temps NTP (ex. pool.ntp.org) NTP UDP 123 Sortant Précision de l'horloge système (indispensable à la validation des certificats TLS et horodatages)
⚠️ Directives pour Pare-feu d'Entreprise & VLAN Invité Stricts
En cas d'installation de GEMS derrière un pare-feu d'entreprise strict, assurez-vous que le trafic HTTPS sortant vers ems.newenergygrid.com n'est pas soumis à une inspection SSL profonde (proxy MITM), sauf si le certificat racine CA de l'entreprise est installé dans le magasin de confiance système Debian (/usr/local/share/ca-certificates/).

3. Procédure d'Appairage & d'Authentification

L'appairage autorise un boîtier edge GEMS physique à transmettre ses données vers un compte client ou site spécifique au sein de GRID-EMS-SERVER. Il repose sur un échange cryptographique sécurisé en deux phases.

3.1 Étapes d'Appairage Pas à Pas

  1. Obtenir le Jeton d'Appairage : Connectez-vous au portail central de gestion de flotte sur https://ems.newenergygrid.com. Accédez à Sites → Add New EMS Node et copiez le jeton matériel généré à 16 caractères (ex. PAIR-8821-X9K2).
  2. Détecter ou Vérifier le Numéro de Série : GEMS extrait automatiquement le numéro de série matériel permanent du SoC Raspberry Pi via /proc/cpuinfo et le préfixe par TCG-EMS- (ex. TCG-EMS-83daf13d05f1adad pour l'identifiant matériel 83daf13d05f1adad). Ce numéro de série est définitivement lié au processeur edge afin de garantir une identité matérielle infalsifiable.
  3. Saisir les Identifiants dans l'Interface GEMS : Ouvrez GEMS Paramètres → onglet Serveur Cloud (Cloud Server). Collez le jeton d'appairage dans le champ correspondant.
  4. Lancer le Handshake : Cliquez sur Pair & Connect Now. Le moteur expédie immédiatement la charge utile d'enregistrement :
POST /api/v1/device/register HTTP/1.1
Host: ems.newenergygrid.com
Content-Type: application/json
User-Agent: GRID-EMS-Agent/9.4.0

{
  "serial_number": "TCG-EMS-83daf13d05f1adad",
  "pairing_token": "PAIR-8821-X9K2",
  "model": "GEMS v9.4 Pro",
  "firmware_version": "v9.4.2",
  "ip_local": "192.168.1.150"
}

Après vérification de la validité et de la disponibilité du jeton d'appairage, le serveur génère un identifiant permanent device_id ainsi qu'un secret cryptographique 256 bits à haute entropie device_secret :

HTTP/1.1 200 OK
Content-Type: application/json

{
  "status": "ok",
  "device_id": 1042,
  "device_secret": "<YOUR_DEVICE_SECRET>",
  "message": "Device paired successfully"
}

Le moteur GEMS enregistre de manière sécurisée les valeurs device_id et device_secret dans la base SQLite locale (table site_settings). Dès cet instant, le jeton d'appairage initial est invalidé et toutes les communications ultérieures utilisent exclusivement le secret cryptographique de l'appareil.

4. Ingestion Télémétrique en Direct & Tampon Hors Ligne Store-and-Forward

5. Diffusion & Exécution des Commandes à Distance

Les opérateurs centraux, installateurs ou agrégateurs de centrales virtuelles (VPP) peuvent transmettre des consignes vers n'importe quelle unité edge via GRID-EMS-SERVER. Lorsque l'unité envoie sa télémétrie, le serveur joint les commandes en attente dans le corps de la réponse :

HTTP/1.1 200 OK
Content-Type: application/json

{
  "status": "ok",
  "device_id": 1042,
  "server_time": "2026-09-07T17:19:55Z",
  "pending_commands": [
    {
      "id": 101,
      "command": "set_strategy_mode",
      "payload": {
        "mode": "flanders",
        "peak_limit_kw": 2.5
      }
    }
  ]
}

5.1 Catalogue des Commandes Distantes Prises en Charge

Nom de la Commande Paramètres du Payload Action Exécutée sur l'Unité Edge
SET_OPERATING_MODE / set_strategy_mode mode : string ("eco", "flanders", "netherlands"), peak_limit_kw : float Met à jour la stratégie d'optimisation active du site avec isolation stricte par pays (applique le plafond flamand peak_limit_kw uniquement sur les unités situées en Flandre et ignore les plafonds régionaux étrangers ailleurs).
SET_BATTERY_MODE device_id : int, mode : string ("auto", "hold", "force_charge", "force_discharge"), target_power_w : float Configure le mode de fonctionnement et la consigne de puissance d'un onduleur hybride ou d'un système BESS autonome avec écrêtage de sécurité automatique.
SET_EV_CHARGE_MODE / SET_EV_CURRENT device_id : int, charge_mode : string ("now", "eco", "pv_only", "off"), max_current_a : float (6–32) Bascule le mode de charge VE ou module dynamiquement l'intensité maximale de la borne via Modbus TCP ou OCPP 1.6-J SetChargingProfile.
TOGGLE_RELAY / set_relay device_id : int, state : bool / int (0 ou 1) Actionne un relais intelligent ou un contact sec pour piloter les états SG-Ready d'une pompe à chaleur ou le forçage d'un ballon d'eau chaude sanitaire.
UPDATE_SETTINGS / SET_FLEET_SETTINGS / SYNC_SETTINGS Champs validés de site, d'automatisation relais ou de flotte VE (ou payload vide pour SYNC_SETTINGS) Applique les paramètres validés de tarifs, d'écrêtage de pointe, de règles relais ou de cluster DLB à la base locale, ou déclenche l'envoi immédiat d'un instantané de configuration assaini (POST /api/v1/device/settings) excluant tout mot de passe ou jeton local.
ADD_HARDWARE_DEVICE / UPDATE_HARDWARE_DEVICE / DELETE_HARDWARE_DEVICE id : int (modification/suppression), template : string, host : string, port / modbus_id / paramètres pilote Ajoute, modifie ou supprime à distance des équipements terrain (tels que les onduleurs hybrides/retrofit Solis, les bornes Raedian, les compteurs intelligents et les relais) dans la base SQLite locale, recharge immédiatement les pollers actifs tout en préservant les mots de passe locaux masqués et renvoie un instantané matériel mis à jour au cloud.
OTA_UPDATE / REBOOT target_tag : string (optionnel, dernière version)
delay_sec : int (défaut 5)		 Lance une mise à jour logicielle OTA vérifiée cryptographiquement (diffusant sa progression sous la source de journal updater avant redémarrage) ou exécute un redémarrage propre du boîtier après acquittement ACK.

5.2 Acquittement des Commandes & Piste d'Audit

Après exécution locale, GEMS acquitte le résultat via une requête POST sur /api/v1/device/commands/{id}/ack en précisant le statut (executed ou failed) et les notes d'exécution. Un journal d'audit complet de toutes les commandes exécutées s'affiche en temps réel dans l'onglet Serveur Cloud de GEMS.

6. Guide de Mise en Service Pas à Pas via l'Interface Web

La mise en service terrain de la connexion cloud prend moins de deux minutes depuis l'interface web GEMS :

Figure 6.1 : Paramètres Cloud Central GEMS — Affichage de l'état de synchronisation actif, de la latence, des champs d'appairage et du journal d'audit.

Étape 1 : Ouvrir Paramètres → Serveur Cloud

Ouvrez le tableau de bord GEMS dans votre navigateur (http://<ip-raspberry-pi>) et cliquez sur Paramètres (Settings) dans le menu latéral. Déverrouillez le mode installateur si nécessaire puis sélectionnez l'onglet Serveur Cloud (Cloud Server) dans la barre d'onglets horizontale.

Étape 2 : Saisir les Identifiants d'Appairage

Vérifiez que le champ Central Cloud Server URL indique https://ems.newenergygrid.com (ou saisissez votre propre serveur auto-hébergé). Collez votre jeton d'appairage à 16 caractères dans le champ Pairing Token.

Étape 3 : Appairer et Tester la Connexion

Cliquez sur Pair & Connect Now. Dès que la carte affiche ● ONLINE & SYNCED accompagné d'un témoin vert, cliquez sur Test Telemetry Push pour contrôler l'ingestion télémétrique de bout en bout. La latence aller-retour est immédiatement mesurée et affichée (généralement 15 à 30 ms).

7. Sécurité, Confidentialité & Garantie d'Autonomie Edge

7.1 Architecture de Sécurité

  • Authentification par Secret Cryptographique : Chaque trame télémétrique est authentifiée à l'aide de l'en-tête unique X-Device-Secret délivré lors de l'enregistrement. Les attaques par rejeu (replay) et l'usurpation sont bloquées par la validation serveur des horodatages.
  • Sécurité de la Couche Transport : Tout le trafic impose strictement le chiffrement TLS 1.3. Toute requête HTTP non chiffrée est immédiatement rejetée par le serveur.
  • Aucune Vulnérabilité sur Port Entrant : Comme GEMS n'ouvre jamais de port public entrant, les scanners Internet malveillants (tels que Shodan) ne peuvent ni détecter ni sonder l'équipement.

7.2 Conformité RGPD & Respect de la Vie Privée

Conformément aux directives européennes sur la protection des données et la minimisation des informations (RGPD) :

  • Zéro Traçage des Véhicules : GEMS applique des règles strictes interdisant la télématique automobile, l'enregistrement du numéro de châssis (VIN) ou le suivi RFID des conducteurs. Seules les grandeurs électriques (puissance de charge en Watts et état du signal pilote) sont transmises.
  • Déconnexion Immédiate à Tout Moment : Le propriétaire peut cliquer sur Disconnect Unit à tout instant depuis l'interface, coupant instantanément les flux cloud et purgeant localement les clés secrètes de l'appareil.
  • Mise en Service & Vérification du Pilotage Matériel à Distance : Lorsque la gouvernance d'accès du propriétaire autorise le mode Full Commissioning & Support, les installateurs certifiés peuvent déclencher la suite en 5 étapes Test Installateur de Mise en Service & Pilotage (Commissioning & Hardware Control Test Suite — vérifiant la télémétrie et la modulation active des consignes sur onduleur/batterie Solis et borne VE Raedian), appliquer des corrections guidées à distance et éditer un certificat officiel de vérification A4 directement depuis GRID-EMS-SERVER ; en mode Read-Only Diagnostics, toutes les commandes actives de test et de correction à distance sont automatiquement bloquées.

8. Dépannage & Diagnostics Terrain

Erreur / Statut Affiché Cause Probable Action Corrective Recommandée
Disconnected / Gris L'interrupteur Cloud Sync est désactivé ou l'unité n'a pas encore été appairée. Activez le commutateur Cloud Sync puis cliquez sur Pair & Connect Now.
Handshake failed: dial tcp: lookup... Échec de résolution DNS sur l'interface réseau locale du Raspberry Pi. Vérifiez les serveurs DNS de la passerelle. Testez via ping ems.newenergygrid.com dans le terminal Cockpit (port 9090).
HTTP 401 Unauthorized Le secret de l'appareil a été révoqué ou supprimé depuis le portail central. GEMS tente automatiquement un ré-enregistrement. Si le jeton a expiré, générez un nouveau jeton dans le portail et relancez l'appairage.
Telemetry push network error: timeout Le routeur local bloque le port sortant 443 ou la bande passante Internet est saturée. Inspectez les règles du pare-feu routeur et assurez-vous que le port TCP 443 sortant est ouvert sans restriction.
Latence Élevée (> 500 ms) Signal Wi-Fi faible ou routeur cellulaire 4G/5G de secours saturé. Raccordez le Raspberry Pi par câble Ethernet Cat6 dédié plutôt qu'en Wi-Fi.
OTA_UPDATE acquitté sans changement de version L'unité exécute déjà une version identique ou plus récente, le téléchargement HTTPS sortant a été interrompu, ou l'unité tourne sur une ancienne version v9.35.1–v9.36.2 nécessitant une mise à niveau locale unique. Consultez les entrées updater dans l'onglet Remote Logs du portail (ou via sudo journalctl -u gems | grep updater), vérifiez l'accès TCP 443 sortant et, si l'unité est en v9.35.1–v9.36.2, installez une fois le dernier paquet .deb via SSH ou le terminal Cockpit (:9090).

8.1 Commandes de Diagnostic Système en Direct

Les installateurs peuvent inspecter en direct les journaux de synchronisation cloud via SSH ou via le terminal web Cockpit intégré (port 9090) :

# Inspecter en direct les journaux de synchronisation cloud
sudo journalctl -u gems -f | grep -i cloud

# Tester la résolution DNS et la connectivité HTTPS sortante depuis l'unité edge
curl -Iv https://ems.newenergygrid.com/api/status

# Vérifier les paramètres du site et l'identifiant cloud enregistré en base locale
sqlite3 /opt/gems/gems.db "SELECT id, cloud_enabled, cloud_server_url, cloud_device_id, cloud_serial_number FROM site_settings WHERE id = 1;"
